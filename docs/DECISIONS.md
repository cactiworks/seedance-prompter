## Решения владельца — 20.09.2026

1. Инструмент локальный, один пользователь, с нуля; старые проекты не переиспользуем.
2. Гибрид: детерминированное ядро работает без LLM; LLM — писатель сценарных абзацев.
3. Доступ к LLM — только подписка Claude Code (Max) через `claude -p`; провайдер за абстракцией.
4. Единица работы — проект из кадров с общим миром и непрерывностью.
5. v1 — один режим «документалка ручной камерой» из гайда; режимы = packs.
6. В v1 входят петля попыток и vision-анализ рефов; LLM-критик и профили full/lean отложены.
7. Дизайн-система — Lab UI v2.1 (Figma Community, CC BY 4.0). Figma Starter. Доступ: REST API по
   токену в Keychain + экспорт переменных плагином. Тема по умолчанию светлая, тёмная поддержана.
   Liquid glass — только на плавающем хроме.

8. **Эталон качества дизайна — сайт lab.pics** (сказано 20.09 после утверждения плана): смотреть, как
   он устроен и структурирован, опираться на него наравне с Figma-файлом. Механизм: разбор в
   `design/lab-ui/REFERENCE.md` + скриншоты эталона в репозитории; в `CLAUDE.md` — обязательное чтение

   Следствие: до получения Figma-файла рабочие значения токенов берутся из измерений живого сайта

   M2 больше не заблокирован целиком ожиданием M0-d — foundations можно начинать по измерениям и
   уточнить по файлу.

9. **Тон галереи `/ui` принят** («да, всё так», 20.09) — стиль размножается на остальные компоненты и
   экраны. **Ссылки на референсы писать как `<<<image_1>>>`** — дефолт диалекта закреплён.

10. **Агент-писатель** (идея владельца 21.09: отдельный агент, обученный под гайд, пишет промпт).
    Принято в форме: агент пишет всё переменное одним вызовом и видит кадр целиком, но дословные блоки
    гайда не перефразирует (их собирает компилятор), номера и реплики ставит плейсхолдерами, а находки
    линтера получает обратно и чинит сам. Почему не «агент пишет весь текст»: дрейф проверенных
    формулировок ломает сравнимость попыток, а механические ошибки (сдвиг номеров, опечатки в
    репликах) LLM сама порождает. Режим «агент пишет всё» — возможный переключатель для A/B.

11. **Камеры не из гайда** (запрос владельца 21.09): телефон (iPhone 15 Pro), цифровой компакт
    (Canon G7 X Mark III), видеокамера MiniDV и «Своя камера» с полями модель / объектив / характер /
    примечание об оптике. Формула стиль-блока та же, что у гайда; характер собран по свойствам техники и
    **генерацией не проверен** — в UI стоит метка «не из гайда», в pack `source: derived | custom`.
    RED собирается и без разделения ролей: приём 06 нужен, только когда такая же техника в кадре как
    реквизит, — теперь это переключатель, а не требование.

12. **Окно проверки** (запрос владельца 21.09: «одна генерация очень дорого стоит»). Правила:
    - *Блокирует копирование* только то, что гарантированно портит генерацию: нет сценария, отрезок
      описан, но не написан, пустая или невычитанная реплика в кадре, неразвёрнутый плейсхолдер,
      герой назван по имени без привязки к референсу, забытое последствие прошлого кадра, кириллица
      вне реплики, чужой синтаксис ссылок, незаполненное разделение ролей, пустое «что брать с рефа».
    - Эвристики по соседству слов (ROLE_FX_ON_PROP) — не выше warning: regex не имеет права жёстко
      блокировать. Любую находку линтера можно скрыть **с обязательной причиной**; причина хранится в
      кадре, список исключений виден и возвращается одной кнопкой.
    - Одна проблема называется один раз (плейсхолдер — блокером с номером отрезка, без дубля в
      находках; кириллица — находкой с самим словом, без дубля в блокерах).
    - Пока сценария нет, правила о сценарии молчат: один блокер NO_SCENARIO вместо пяти находок.
    - Линтер знает диалект: реплика в `{скобках}` — не «кириллица вне реплики»; речь считается по
      вставленным репликам, а не по кавычкам.
    - То, что линтер проверить не может (порядок картинок в Higgsfield, модель/формат/длительность,
      Enhance Prompt, просмотр предупреждений), — чек-лист у кнопки копирования; любая правка
      промпта сбрасывает отметки.
    Механизм: `tests/core/findings.test.ts` — «чистый кадр» обязан давать ноль блокеров, ошибок и
    предупреждений на каждом комплекте и в обоих диалектах; каждое срабатывание — отдельным тестом.

13. **Длительность — параметр кадра** (запрос владельца 21.09). `shot.durationSec` (целое 4–30, `null` —
    как у ролика): каждый кадр — отдельная генерация. Формула формата в pack остаётся дословной под
    30 секунд; компилятор меняет в ней только число, при 30 с текст байт в байт. От длительности
    считаются ёмкость речи, бюджет событий (4–6 на 30 с → пропорционально) и допустимое число отрезков
    планировщика; агенты получают `durationSec` и `majorEvents` во входе. Правило DURATION_MISMATCH
    ловит «30-second take», вписанное в абзац руками. В гейте копирования — «длительность N с».
    Недопечатанное или недопустимое число в поле в промпт не попадает: действует последнее верное.

14. **Критик — не оракул готовности** (запрос владельца 22.09: «итоговая проверка агентом»). LLM, которая
    говорит «всё готово», не видела генерацию — это ложная уверенность. Поэтому критик отдаёт две
    проверяемые вещи: *readback* — пересказ по абзацам, что увидит зритель, с местами, где он не уверен
    (расхождение с замыслом видно без генерации), и *находки за пределами regex* — физика, причинность,
    роли, двусмысленности, с дословной цитатой. Вердикт есть, но как мнение с обоснованием; ничего не
    блокирует. Один агент, не несколько: на таком объёме мультиагентность добавляет цену и латентность, а
    не качество. Механизмы: `verifyCritique` выбрасывает находку, чьей цитаты нет в тексте, и не даёт
    вердикту быть мягче найденного; критик получает находки линтера и осознанные исключения, чтобы их не
    повторять; список проверенных приёмов гайда (камера в салоне второй машины, отражение оператора…),
    которые сами по себе не флагуются — добавлен после первого прогона, где приём 04 был помечен как
    critical. Запуск только по клику и только без блокеров: квота не тратится на несобранный промпт.
    Модель по умолчанию sonnet (`SP_CRITIC_MODEL`), таймаут 300 с.

15. **Осознанный пропуск критика.** Ядро работает без LLM, поэтому критик не обязателен, но пропуск —
    выбор, а не забывчивость: в чек-листе перед копированием стоит либо «Замечания критика (N)
    просмотрены», либо «Иду без итоговой проверки критиком — осознанно». Если критик читал этот текст и
    замечаний нет — пункт закрыт машиной.

16. **Карточка «Кадр → Higgsfield»** (запрос владельца 22.09). Всё, что переносится, в порядке действий
    там: настройки (модель, 9:16, длительность, Enhance Prompt выкл) → референсы по номерам с кнопкой
    «сложить в папку 01-…, 02-… и открыть в Finder» → промпт → пересказ критика «что должно получиться»
    → чек-лист → «Скопировать» и «Сохранить как попытку». Пересказ критика уходит в попытку
    (`readbackRu`): после генерации есть с чем сравнивать. Папка экспорта пересобирается с нуля при
    каждом вызове, чтобы старая нумерация не лежала рядом с новой.

17. **Один референс локации.** Формула гайда написана под два («exactly as in N and N»); с одним
    компилятор схлопывает пару до одного номера — критик прочитал дубль как опечатку. Двухреференсный

2. **«Размер» / апскейл меняли вид выхода, а связь во вход картинки оставалась.** `dropStaleEdges` (ядро) снимает
   связи, которые новый выход не принимает, — вызывается в `connect`. Для импортированных flow — проверки в `planRun`
   и `frameInput`.
3. **Снятый и возвращённый проводок Seedance-промптера перезаливал ту же картинку и сбрасывал флаги vision.**
   `nextRefSync` хранит отпечатки, пока референс есть в черновике.
4. **Кадры раскадровки считались предметами:** попадали в выбор техники-реквизита (приём 06) и давали
   REF_PEOPLE_ON_OBJECT_REF. Один признак `isObjectRef` для обоих мест.
5. **Метод гайда + склейки помечал блок формата «дословным»**, хотя формула склеек не из гайда. Теперь «derived».
6. **Удаление файла оставляло ссылки в canvas.** Сервер чистит сохранённые flows (`forgetMedia`) при удалении файла и
   задачи; открытый flow чистит клиент, иначе автосейв вернул бы ссылку.
7. Видео для апскейла читалось в память дважды — первый файл берётся из замера.
8. Блок вариантов ‹ n/N › был в двух копиях — `VariantResult`.
9. Поиск файла задачи был в четырёх копиях — `savedMediaOf`.

## Архитектурные решения — 20.09.2026

- **Subprocess `claude -p`, а не Agent SDK.** Документированный личный сценарий, команду можно
  скопировать в Терминал, `--safe-mode` доступен напрямую. Agent SDK — план Б за тем же интерфейсом.
- **`--safe-mode`, а не `--bare` и не `--restricted`.** `--bare` отключает OAuth подписки;
  `--restricted` не покрывает CLAUDE.md и коннекторы. Механизм: tripwire по `system/init` на каждом
  вызове + `npm run doctor`.
- **Env дочернего процесса по allowlist.** `ANTHROPIC_API_KEY` в окружении молча уводит биллинг на API.
- **Хранится `TextUnit`, блоки производные.** Ручная правка не теряется при перегенерации; provenance
  даёт переход из превью в поле-источник.
- **Один процесс: Hono + Vite middleware, нативный TS Node 26.** Нет `dist` и расхождения dev/prod;
  откат — `tsx`.
- **Без Tailwind и shadcn.** Lab UI задаёт собственную шкалу; UI-kit на CSS Modules + Radix.
  Механизм: stylelint запрещает всё, кроме `var(--lab-*)`.
- **Pack извлекается скриптом из `guide.html`**, а не перепечаткой: в разметке гайда есть спаны семи
  категорий подсветки и `look-data`. Механизм: `verbatim.lock.json` + побайтный golden-тест.

- **pre-commit hook гоняет `npm run check`** (21.09). Причина: коммит e3ba6eb прошёл с красным stylelint —
  проверка запускалась через `| grep`, который маскирует код возврата. Механизм: `.githooks/pre-commit` +
  `git config core.hooksPath .githooks`; после клонирования эту настройку нужно выставить заново.

### M0-d · инцидент с токеном — 20.09.2026
