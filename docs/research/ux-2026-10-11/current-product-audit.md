# Аудит текущего продукта: путь AI-креатора

Дата: 11 октября 2026. Первый рассматриваемый сегмент — креаторы, которые делают рекламные материалы и контент для клиентов. Цель владельца: централизованный рабочий цикл с Canvas как основным пространством, от references и генерации изображения до правки, видео, небольшой обрезки и экспорта.

**Главный вывод:** значительная часть нужных операций уже реализована, но собрать из них законченный рабочий процесс должен сам пользователь. Canvas связывает генерации, однако не является главным входом и не предоставляет полный набор действий над результатом. Onboarding поможет объяснить механику, но сам по себе не устранит эти разрывы.

- **Браузер:** основной исследователь в этой же задаче увидел начальный экран `/shots` с заголовком «Промпт, в который верит модель», Canvas пятой вкладкой, шаблон «Картинка → видео» с четырьмя формами, занявшими большую часть экрана при viewport 1280 × 800 (preview снимка 1024 × 640), и кнопку экспорта flow в JSON. Это наблюдения основного исследователя; автор code audit не проводил отдельную hands-on сессию. ## Следствия для наброска и onboarding

1. Главная единица — **проект клиента**, основная рабочая поверхность — **Canvas**. Существующие assets, sessions и jobs связываются с проектом; это целевая модель, не описание текущей реализации.
2. Один asset inspector открывается из ноды и библиотеки. Действия: изменить, сделать вариант, анимировать, обрезать, подготовить формат, экспортировать. Операции возвращают связанную версию и сохраняют исходник.
3. Универсальный prompt assistant доступен в выбранной генерации. Seedance-конструктор — расширенный режим видео с ясной кнопкой возврата в проект.
4. Images/Video можно сделать фильтрами assets и быстрыми действиями. Calibration — служебная функция для опытного пользователя; её равный вес с Canvas в текущей навигации не следует сохранять автоматически.
5. Общая очередь проекта показывает состояние, стоимость, ошибки и безопасный recovery; пользователь видит, к какой ноде относится job.
6. Первый onboarding проводит по одному завершённому пути на demo assets: reference → image → правка → video → trim → export. Он не требует платного запуска, не объясняет семь вкладок подряд и доступен повторно через Help. Canvas-механика объясняется в момент действия.
7. Первый сегмент следует проверять на клиентских сценариях: продолжить заказ после перерыва, сделать два варианта, сохранить выбранный результат, внести локальную правку, подготовить 9:16/1:1, собрать понятный пакет для передачи. Общий brief, версии и finals — гипотезы требований для проверки с креаторами, а не подтверждённые интервью потребности.

## Что ещё не установлено

- Не проверены реальная успешность генераций, качество моделей, latency и списания: платных запусков не было.
- Не измерены время до первого результата, число ошибочных переходов и понятность названий у целевой аудитории.
- Плотность четырёх форм при viewport 1280 × 800 подтверждена одним браузерным наблюдением; это не полный responsive или accessibility audit.
- Текущие docs описывают single-user localhost приложение на Mac. [CLAUDE.md:3](/Users/matveylytkin/Documents/вайбк/seedance-prompter/CLAUDE.md:3). Для новой аудитории остаётся продуктовый выбор: локальное приложение со своими ключами либо общий сервис. От него зависят provider setup, доступ и хранение; текущую Keychain-интеграцию нельзя считать завершённым onboarding внешних пользователей.
