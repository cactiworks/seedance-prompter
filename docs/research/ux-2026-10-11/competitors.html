Конкурентные UX-patterns для AI production

Дата проверки: 2026-10-11. Первый сегмент: AI-креаторы, делающие рекламу и контент для клиентов. Целевой цикл: references → image → edit → video → trim/assembly → delivery → клиентская правка.

Уровень Ф3 в этом файле означает: исследователь лично открыл официальный первичный документ и проверил описанную механику. Это утверждение производителя о продукте, а не hands-on проверка функции, её качества, надёжности или востребованности. Конкурентные patterns помогают сформулировать гипотезы; они не заменяют интервью и тесты с пользователями Seedance Prompter.

Отдельная проверка ведущего исследователя в Yab: открыты Higgsfield Canvas landing, список templates и форма Image. Генерации и workflow не запускались. Эта проверка подтверждает наличие видимых экранов, но не весь описанный ниже функционал.

Runway Workflows Quick generation отделена от повторяемых workflows. Templates, обязательные inputs, совместимые типы, lock готового node, Active Runs. Introduction. History позволяет favorite, восстановить старый output и превратить его в отдельный image node. First workflow Сохранить approved кадр и пересчитать только следующую операцию; вернуть старый результат без повторной оплаты генерации.
Krea Edit открывается поверх выбранного изображения с уже загруженным asset; history strip хранит промежуточные edits. Edit. Node Agent читает текущий canvas, показывает план и стоимость по nodes до запуска, позволяет менять этапы и модели. Node Agent Prompter учитывает выделенный asset и его задачу. Помощь доступна непосредственно в работе, а цену видно до генерации.
Figma Weave, ранее Weavy Workflow превращается в Tool с выбранными inputs и скрытыми/locked parameters. Получатель видит простой интерфейс без canvas; изменения публикуются отдельно. Версии Tool сохраняются с timestamp. Tools Шаблон клиентской задачи можно начать с нескольких полей и раскрыть Canvas для тонкой настройки. Canvas остаётся центральной моделью работы, ручная сборка графа не обязательна на старте.

Дополнительные механики клиентской работы — Ф3

  • Отбор и delivery. FLORA описывает color tags, фильтрацию результатов и ZIP выбранной группы; Review включает варианты из history. Unified Library и project folders помогают возвращаться к работе. На image result доступны действия remove background, mark up и video; после первого результата появляется contextual nudge о других инструментах. FLORA, 2026-09-11
  • Понятные расходы и экспорт. FLORA позволяет переключать usage между credits и USD, экспортировать в выбранную Drive-папку с именами файлов и предотвращением перезаписи. FLORA, costs/export
  • Восстановление контроля. FLORA описывает cancel текущей генерации с возвратом node к прежнему состоянию, объяснение несовместимых connections и clear output с сохранением prompt/model/settings. Источник не обещает refund при cancel. FLORA, 2026-10-06
  • Простой режим поверх графа. Runway App скрывает выбранные inputs/outputs и фиксирует важные параметры исходного workflow. Publishing Workflows as Apps

Website и API: границы обещаний

Higgsfield — Ф3. API использует отдельный USD balance; web subscription, credits и Unlimited туда не переносятся. API catalog может отличаться от сайта. Официальный help описывает estimate endpoint, asynchronous jobs с polling/webhook, оплату успешных запросов и возврат суммы при failed request. Outputs доступны минимум 7 дней, после чего могут удаляться: для постоянной библиотеки требуется собственное хранение. Standalone audio models в API catalog не заявлены; у некоторых video models есть native audio. API help, 2026-09-16

KIE — Ф3. Актуальная открытая документация указывает хранение generated files 14 дней и рекомендует сохранять результат. Она также описывает загрузку актуальных параметров выбранной модели перед запросом. KIE: What your agent can do

Расхождение с локальными заметками, требует проверки adapter. В DECISIONS.md и kie-models.md зафиксированы прежние сообщения о сроке URL 24h одновременно с 14-дневным хранением медиа. Нельзя автоматически считать, что это один и тот же срок: срок ссылки, оригинала и хранения файла могут различаться. Это drift/неуточнённый контракт, который нужно проверить для текущего endpoint в adapter; оснований ослаблять немедленное сохранение outputs нет.

Наличие Canvas, Studio или иной функции на сайте провайдера не доказывает наличие доступного API endpoint. Для каждого обещанного действия нужна проверка конкретных model, endpoint, inputs и outputs. Постоянное хранение, history, trim и сборку exports следует учитывать как возможности самой платформы, если они реализуются локально.

Пять выводов для Seedance Prompter — проектные гипотезы

  1. Проект организует работу, Canvas показывает её ход. Brief, references, shots, variants, jobs и exports принадлежат одному проекту. Images/Video могут быть фильтрами общей библиотеки; пользователю не нужно заново собирать контекст между вкладками.
  2. Вход начинается с deliverable, продолжение — с выбранного asset. Шаблоны «Предметный ролик», «Реклама с персонажем», «Серия визуалов», «Оживить кадр» создают стартовую структуру. Действия Edit / Variations / Animate / Trim / Export автоматически передают asset дальше и показывают результат на Canvas.
  3. Итерация сохраняет одобренное. Нужны selected/favorite версии, фиксация approved shot, ветка клиентской правки, возврат старого результата и явный scope повторного запуска. Экспорт должен собирать отобранные версии с понятными именами, а не всё содержимое проекта.
  4. Prompter работает внутри операции. Он учитывает выделенный asset, роль references и текущий этап: образ для image, движение/camera/timing для video. Перед запуском видны inputs, модель, ограничения и оценка цены. Достаточно начать с contextual assistant; большой автономный agent не является обязательным условием.
  5. Onboarding ведёт до небольшого законченного результата. Практический маршрут reference → image → edit → animate → trim/export показывает связь частей. Повторяемый обзор с подсветкой полезен как помощь. Самостоятельное выполнение клиентской правки на следующий день проверяет понимание лучше, чем прохождение tooltip-tour.

Основной тест для первого сегмента: загрузить товар и style reference → сделать три варианта → выбрать и поправить один → получить video → обрезать → выгрузить final → выполнить правку клиента, сохранив уже одобренные части. Конкурентный research не устанавливает частоту этих потребностей у конкретных пользователей: приоритеты нужно проверить наблюдением за их реальными задачами.
