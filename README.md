# Seedance Prompter

Локальная система AI-креатора: конструктор промптов Seedance 2.5 по правилам гайда Cinema Ai Tech,
промптер под другие модели, генерация картинок и видео через KIE и Higgsfield API, canvas и библиотека.
Поля заполняешь по-русски — английский пишут агенты; референсы нумеруются автоматически, промпт
проверяет линтер, попытки ведутся журналом.

Код опубликован в `cactiworks/seedance-prompter` по решению владельца. Фото, проекты, история
генераций и API-ключи остаются на каждом компьютере и не входят в GitHub.

## Запуск

Двойной клик по `Запустить.command` — откроется вкладка `http://127.0.0.1:4317`.
То же из терминала: `npm start`. Остановить — `Ctrl+C` в окне терминала или просто закрыть его.

Запуск проверяет GitHub и ставит зависимости из `package-lock.json`, если они изменились.
Сначала настрой роль компьютера по инструкции ниже. ZIP — разовый снимок, без автообновления.

## Два Mac: установка и обновления

На втором Mac нужны Git, Node ≥24, Codex CLI с входом в ChatGPT и ffmpeg/ffprobe.
Сохрани прежнюю ZIP-папку отдельно, особенно её `data/`. В новой свободной папке:

```bash
git clone https://github.com/cactiworks/seedance-prompter.git
cd seedance-prompter
npm run sync:replica
npm start
```

После этого запускай `Запустить.command` или `npm start`: перед стартом выполняется fetch
и обновление `main` только через fast-forward. При локальных изменениях, другой ветке,
расхождении истории или отсутствии сети запуск получателя останавливается с объяснением.
Явный запуск имеющейся версии без обновления: `npm run start:offline`.
Если приложение уже работает, файлы не меняются: сначала `Ctrl+C` в его окне, затем новый запуск.
Открытие вкладки браузера само по себе не перезапускает сервер.

На основном Mac один раз выполнено `npm run sync:source`. Codex после завершённой задачи
сохраняет её изменения в commit; pre-commit проверяет код, post-commit отправляет чистую `main`
на GitHub. Роль хранится только в локальном Git config и не переносится на второй Mac.
Если сеть или авторизация мешают push, commit остаётся локально; повтор отправки — `npm run publish`.
`npm run sync:status` показывает режим, локальную версию и фактическую версию GitHub.

Проекты и медиа из старой ZIP-копии можно отдельно перенести через `data/` при остановленных
приложениях, предварительно сохранив обе папки. Автоматической синхронизации данных нет.
Ключи Higgsfield/KIE на втором Mac настраиваются отдельно в Keychain; Codex тоже требует входа.

Текстовые и визуальные агенты работают через Codex / OpenAI. KIE и Higgsfield — только
генерация и обработка медиа. Основные инструкции для агента разработки — `AGENTS.md`.

## Production: Codex → реальные фото

Открой «Производство» (`#/production`) → «Новая серия». Напиши сценарий и визуальный вектор,
выбери Phone / UGC или Cinematic и нажми «Подготовить с Codex». Режиссёр создаст единый паспорт
сцены и 1–8 кадров; второй агент подготовит prompts фото и движения. Свет, одежда, композиция,
допущения и предупреждения видны в первом этапе. Prompts доступны для чтения внутри каждого кадра.

Кнопка расходует квоту ChatGPT: обычно два вызова, до четырёх при исправлении некорректного
структурированного ответа. Счётчик завершённых вызовов и полученный token usage видны в серии.
Отправляются только сценарий, вектор и стиль; история чата, профиль и фото лица не подключены.
`SP_PRODUCTION_MODEL` меняет модель подготовки; иначе используется `SP_LLM_MODEL` / `gpt-6-astra`.

При ошибке уже готовая сцена сохраняется. «Повторить этап Codex» повторяет только незавершённую
роль и снова расходует квоту. Пауза прерывает вызов; после продолжения повтор подготовки запускается
отдельной кнопкой. После перезапуска сервера незавершённый Codex сам не запускается.

После подготовки нажми «Рассчитать стоимость фото». Подтверди оценку и передачу prompts,
reference сцены и выбранного Soul ID в Higgsfield. Создаётся один опорный кадр Soul 2, затем
1–8 кадров по плану с этим изображением как reference. Все фото — 1080p, 9:16; Phone / Cinematic
задают манеру съёмки одной модели Soul 2. По каталогу приложения — $0.006 за изображение,
включая опорное ($0.012–0.054 за серию). Это оценка, фактическое списание определяет Higgsfield.

На milestone появляются только скачанные файлы. Проверь лицо, руки, одежду, свет и общую сцену,
выбери подходящие и нажми «Принять фото». Фото сохраняются в «Материалах» и доступны для скачивания.
Автоматического visual QC, editing, видео и upscale в этом режиме пока нет.
Пауза/перезапуск останавливают будущие отправки; известные задачи продолжают проверяться.
Оставшиеся кадры требуют нового подтверждения цены. Unknown submit не повторяется; retry доступен
только для скачивания/таймаута опроса уже созданной задачи. Сверяй неизвестную отправку в Higgsfield.

Старые серии с заглушками сохраняются. «Реальные фото по этому плану» создаёт отдельную серию
с теми же сценой и prompts, без повторного вызова Codex и без переноса mock-приёмок.

**Персонаж серии (Soul ID).** В новой или существующей серии нажми «Выбрать персонажа» →
«Новый персонаж». Добавь 1–100 JPG/PNG/WebP до 30 МБ каждое и имя. Сначала фото сохраняются
локально; перед «Создать Soul ID · цена неизвестна» отдельно подтверди передачу фото в Higgsfield
и возможное списание: цена обучения в документации не опубликована. Это отдельная операция,
не часть бесплатного mock-прохода. Ключ читается из Keychain, фотографии не отправляются Codex.
После статуса «Готов» выбери персонажа для серии. Выбор переживает reload и входит в manifest;
в реальной серии Soul ID применяется к опорной сцене и всем кадрам. После начала фото выбор фиксируется. «Обновить из Higgsfield» читает список аккаунта, ничего не создаёт.
Если API не сообщил версию импортированного Soul ID, выбор заблокирован до подтверждения v2.
При неизвестном результате отправки сначала проверь кабинет Higgsfield: автоповтора нет.

Для полностью бесплатной демонстрации выбери «Демо без генераций»: сцена, три кадра и prompts фиксированы,
LLM не вызывается. Старые mock-серии сохраняют этот режим. Все серии лежат отдельно в
`data/production-mock/`. После обновления серверного кода перезапусти сервер.

## Где что лежит

- `data/` — твои проекты, референсы, попытки. Обычные файлы, в git не попадают. Бэкап — скопировать папку.
- `.agents/skills/project-knowledge/` — как устроено сейчас. `docs/DECISIONS.md` — почему так и чек-лист ручных
  действий. `docs/BACKLOG.md` — статус этапов и что дальше. `docs/archive/` — исходный план 20.09.
- `packs/cinema-doc/` — правила гайда как данные. `docs/source/` — снимок самого гайда.
- `design/lab-ui/` — всё, что вытянуто из Figma-файла дизайн-системы.

## Если LLM не отвечает

Инструмент вызывает локальный `codex exec` с входом в ChatGPT. Проверь `codex login status`;
если вход истёк — выполни `codex login`. При исчерпанном лимите работает всё, кроме агентов: «Собрать промпт», критик,
vision, промптер, перевод правки. Модель по умолчанию — `gpt-6-astra`; `SP_LLM_MODEL` меняет её
для всех ролей, а `SP_FIELDS_MODEL`, `SP_WRITER_MODEL`, `SP_CRITIC_MODEL`, `SP_VISION_MODEL`,
`SP_PROMPTER_MODEL`, `SP_EDIT_MODEL` переопределяют отдельную роль. Старые aliases `sonnet`/`opus`
не используются. Живые вызовы расходуют квоту аккаунта. Проверки адаптера не заменяют живую
калибровку качества конкретной модели.

Бесплатная диагностика — `npm run doctor`: наличие CLI, вход в ChatGPT и настройки изоляции,
без inference. `npm run doctor -- --live` запускает владелец: это отдельный LLM-зонд с расходом
квоты, а не обязательная часть обычной проверки.
