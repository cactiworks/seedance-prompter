# Seedance Prompter

Система AI-креатора, выросла из конструктора промптов Seedance 2.5. С 19.10.2026 рабочая студия
на сервере владельца: общая data, HTTPS через Netlify/Caddy. Локальный Mac — разработка/откат. Как устроено сейчас — `.agents/skills/project-knowledge/` (роутер `SKILL.md`); почему так —
`docs/DECISIONS.md`; что дальше и статус этапов — `docs/BACKLOG.md`.

## Нельзя

1. Remote `cactiworks/seedance-prompter` публичный по прямому решению владельца 14.10.2026
   «отправь в публичный». Разрешение относится к коду проекта; личные данные, фото, ключи,
   `data/` и новые чужие материалы в публикацию не включать. Перед commit проверять staged diff.
2. Не править руками `packs/cinema-doc/verbatim.json` «для улучшения»: формулировки гайда дословные,
   sha256 каждой — в `verbatim.lock.json`, побайтный golden-тест это ловит.
3. Не писать сырые цвета, радиусы, тени в CSS приложения — только `var(--lab-*)` (stylelint-гейт).
   `src/web/ui/tokens/tokens.css` генерируется `scripts/design/build-tokens.ts`, руками не правится.
4. В `src/core` нет `node:*`, `react`, DOM — ядро обязано работать в браузере и в Vitest.
5. LLM никогда не запускается без клика пользователя. Генерация (KIE, Higgsfield) — тоже только по клику
   и через гейт стоимости: сервер отклоняет задачу, если подтверждённая сумма не равна оценке (решение 21).
   Прерванную отправку задачи сервер сам не повторяет: у провайдеров нет идемпотентности, это деньги.
   **Платные прогоны запускает только владелец** (02.10: «все прогоны за деньги я буду делать сам»): агент не жмёт
   генерацию ни в браузере, ни запросом к `/api/gen/jobs`, даже с «да» в разговоре — готовит, проверяет бесплатно и
   называет цену. Механизма нет, здесь только текст.
6. На Mac секреты — только в macOS Keychain (`figma-pat-lab-ui`, `kie-api-key`, `higgsfield-api-key`), в контексте
   и файлах — только имя записи. Ключи не кладутся в `process.env`: дочерние LLM-процессы получают
   только разрешённые переменные окружения. На Linux по решению владельца 19.10.2026 ключи
   провайдеров передаются через файлы root:seedance с доступом только root и сервисной группе; значения не попадают
   в env, Git, логи и контекст. Данные и адреса конкретного deploy — вне публичного Git.
   Личные API-подключения на сервере хранятся в изолированном Codex profile внутри SP_ACCOUNTS_DIR
   (0600/0700), вне shared data; импорт ключа только через stdin. Browser status ключ не возвращает.
7. Не добавлять в форму полей для английского ввода. Владелец пишет тезисы по-русски, английский делают
   агенты (агент полей, писатель) и показывается только для чтения (решение 18 в `docs/DECISIONS.md`).

## Роль Codex

Codex — основной агент разработки и сопровождения. Продуктовые текстовые и визуальные агенты
работают через Codex / OpenAI; Higgsfield и KIE используются только для генерации и обработки медиа.
Каждый продуктовый вызов получает подготовленное задание, а не историю этого чата, личный профиль
или контекст консилиума. Production по клику владельца вызывает две роли Codex: режиссёр
(по сценарию — смысловые события; B-roll — независимые визуальные идеи по вектору, 1–8 кадров; паспорта локаций и одежда), затем prompts проверочного master и кадров. Режим photos создаёт
реальные фото Soul 2 после отдельного numeric cost gate: профиль внешности по локальным refs → master →
обязательный критик master → независимые T2I кадров с Soul ID. Новые plans events-v1 не передают
композицию master как reference. Legacy планы сохраняют прежний I2I маршрут. Без положительного master report
новые кадры запрещены сервером. Критик проверяет персонажа целиком, лицо, руки, событие и стартовую композицию;
continuity относится к конкретной сцене, запланированные разные локации допустимы;
готовые фото отбирает владелец галочками. До шести локальных фото Soul ID используются для фиксации внешности и проверки master/серии
по отдельному masterGateConsent при cost gate. Новое masterRetryConsent разрешает до трёх master
всего (до пяти Codex-вызовов вместе с внешностью и финальным отбором); старое согласие не расширяется.
Мелкие отличия одежды/ракурса и художественных эффектов допустимы; внешность, анатомия, комплект одежды и физическая логика сцены обязательны. B-roll делает владельца главным героем и использует простую постановку. Новый критик получает общий вид и фрагменты, отдельно проверяет глаза/рот и дефекты; старые оценки меняются только после явной перепроверки.
В story явные указания сцен имеют приоритет над свободной трактовкой; число позиций следует сценарию без лимита восемь. «Продолжить» принимает отмеченные фото и после отдельного numeric cost gate пересоздаёт только неотмеченные позиции. Принятые кадры сохраняются, серия готова лишь при закрытии всех позиций. Обязательных автоправок после выбора нет; дальнейшие правки — по желанию в Canvas. Старые retouch-задачи и их история сохранены. Принятые фото переходят в связанный Canvas Flow: агент заполняет Seedance Prompter по серии, критик допускает одно исправление. Видео запускается владельцем отдельно через Higgsfield с account estimate либо явно подтверждённым ориентировочным tariff; auto-upscale отключён. Режим mock сохраняет демонстрацию. Soul ID управляется отдельно: локальная загрузка фото,
явное создание v2 в Higgsfield, статус и выбор готового персонажа для серии. Создание требует
согласия на передачу фото и подтверждения неизвестной стоимости; автоматического повтора нет. Режим «Демо без генераций» не вызывает и LLM.
Пауза/рестарт не повторяют Codex автоматически; сохранённую сцену использует явный retry.

## Команды

- `npm start` — запуск для владельца (один процесс: Hono `/api/*` + Vite middleware), порт 4317.
- `npm run dev` — то же с watch.
- `npm run check` — `tsc --noEmit && eslint && stylelint && vitest run && vite build`. Единственный
  критерий «готово» для сессии.
- `npm run doctor` — бесплатная проверка CLI, входа ChatGPT, окружения и количества отключённых
  local skills; без LLM-вызова. `npm run doctor -- --live` — зонд схемы/латентности, расходует квоту
  и запускается владельцем.
- Второй экземпляр для проверки, пока основной занят: `SP_SKIP_UPDATE=1 SP_PORT=4318 SP_DATA_DIR=<временная папка> SP_NO_OPEN=1 npm start`
  (своя папка данных — иначе два фоновых опроса делят одни задачи).
