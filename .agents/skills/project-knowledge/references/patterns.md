# Правила и проверки

## Инварианты модели и компилятора

Ломать нельзя; большая часть держится тестами.

1. **Номера ссылок на референсы руками не пишет никто.** В тексте — плейсхолдеры `{{intro:key}}`,
   `{{ref:key}}`, `{{line:L3}}`, `{{state:S1}}`; компилятор разворачивает их в диалект по порядку панели
   этого кадра. Неразрешённый плейсхолдер блокирует экспорт; неизвестная ссылка молча не удаляется.
2. **Реплики и языковую фразу LLM не пишет**: реплика уходит в промпт буква в букву через `{{line:Ln}}`.
   Фразу последствия (`{{state:Sn}}`) пишет агент полей из русского описания — сторона, степень,
   ограничитель; писатель только ставит плейсхолдер, ответ без нужного последствия отклоняется
   (решение 18).
3. **Формулировки гайда — дословно из pack.** `verbatim.json` руками не правится; sha256 каждой —
   `verbatim.lock.json`; golden-тест собирает промпты гайда байт в байт.
4. **Отрезок = абзац = `Segment`, 1:1.** Хранится `TextUnit`, блоки промпта производные.
5. **Диалект — настройка проекта.** По умолчанию ссылки `<<<image_N>>>` (решение 9); как их называет
   модель при отправке провайдеру — [generation.md](generation.md). Формат: в методе гайда компилятор
   меняет в дословной формуле только «Vertical 9:16» и число секунд, при 9:16 и 30 с текст байт в байт
   (решения 13, 19); формулы других режимов и склеек — из `shooting.json`, помечены derived (решение 37,
   ревью PR #1).
6. **Режимы съёмки и монтаж — данные `shooting.json`.** Метод гайда собирается байт в байт (golden и
   `tests/core/shooting.test.ts`); остальные режимы помечены «не из гайда» и правятся по живым
   прогонам (решение 37).
7. **В форме «Кадров» нет полей английского ввода.** Английский пишут агенты и показывают только для
   чтения (решение 18). Студии, canvas и правки это не касается: там промпт пишется напрямую. Механизма
   нет — держит только правило в `AGENTS.md`.

## Линтер и окно проверки

- Правило линтера — код в `src/core/lint/rules/`; пороги — `packs/cinema-doc/lint.json`, словари —
  `packs/cinema-doc/lexicon.json`.
- `error` — только гигиена, референсы, роли и непрерывность. Эвристика по соседству слов не выше
  warning: regex не имеет права жёстко блокировать.
- В Seedance-промптере «Не исправлять» снимает находку линтера, требование к содержанию или
  замечание критика одним кликом. В `shot.suppressed` сохраняются текст замечания и причина
  «Не влияет на результат этого кадра — решение владельца»; прежние ручные причины поддерживаются.
  Исключения видны и возвращаются кнопкой «Вернуть». `src/core/review.ts` одинаково применяет решения
  в браузере и на сервере: требования привязаны к входам/промпту, критик — к версии отчёта и находке.
  Неразрешённые плейсхолдеры и ошибки pack снять нельзя. Без референса локации сборка оставляет
  текстовое описание места без фиктивной ссылки; в методе гайда NO_LOCATION_REF остаётся до решения владельца.
- Блокеры окна проверки — только то, что гарантированно портит генерацию (решение 12). Одна проблема
  называется один раз. Пока сценария нет — один блокер `NO_SCENARIO`. Изменения после сборки —
  один блокер `NEEDS_COMPOSE` (решение 18). Чистый кадр даёт ноль находок на каждом комплекте и в обоих
  диалектах — `tests/core/findings.test.ts`.

## Агенты

- Ответ агента проверяется схемой (`--output-schema` и проверка результата в приложении). Писатель, агент полей, планировщик, промптер и
  инструкция правки проверяются ещё и правилами (`validate*` в `src/core/llm/`), с ремонтным кругом: на
  провал прежний текст сохраняется, нарушения показаны. У критика находки фильтрует `verifyCritique`,
  ремонта нет; у vision — только схема. Меняешь схему ответа — правь и её валидатор.
- Критик — не оракул готовности: находка без дословной цитаты из текста выбрасывается
  (`verifyCritique`), вердикт не мягче найденного, запуск только без блокеров (решение 14). Пропуск
  критика — осознанная галочка в чек-листе (решение 15).
- Промптер (`validatePrompter`): модель из кандидатов, параметры из вариантов модели, кириллица только в
  кавычках, каждая отправленная картинка названа; для Soul 2 — до 200 слов и без отрицаний (решение 28).
  Какие картинки получит модель, решает код (`routeRefs`), не агент (решение 29).
- Seed, Soul ID и «улучшать промпт» — поля владельца; агент их не выбирает.
- Правило из прогонов — с третьего повтора одной ошибки у одной модели: журнал предлагает, владелец
  дописывает, правило уходит в карточку модели разделом `[owner]` (решение 33).

## Код

- Node 26 исполняет TS нативно: `erasableSyntaxOnly`, импорты с расширением `.ts`, только относительные
  пути, без enum, namespace и parameter properties.
- В `src/core` нет `node:*`, `react`, серверных библиотек и импортов из `server` / `web`; в `src/web` нет
  Node API и импортов сервера, кроме типов API. Держит ESLint `no-restricted-imports`
  (`eslint.config.*`).
- В CSS приложения только `var(--lab-*)` — stylelint (см. [ux-guidelines.md](ux-guidelines.md)).
- Сообщения пользователю — по-русски.
- Набор моделей и рецептов проверяют тесты данных: `validateFixPack`, `validateCalibration`, связи
  шаблонов canvas — проверка портов и циклов.

## Проверки

- `npm run check` = `tsc --noEmit` + eslint + stylelint + vitest + `vite build` — единственный критерий
  «готово» для сессии.
- `.githooks/pre-commit` гоняет `npm run check`: красный коммит не проходит (включение хуков после
  клонирования — [deployment.md](deployment.md)).
- Сервер тестируется через `app.request()` без портов (`tests/server/`); ядро — `tests/core/`.
- Живая проверка интерфейса — вторым экземпляром на своей папке данных
  (см. [deployment.md](deployment.md)), не на рабочем.

## Секреты и данные владельца

- Ключи только в macOS Keychain: `figma-pat-lab-ui`, `kie-api-key`, `higgsfield-api-key`. В файлах и
  контексте — только имя записи. В `process.env` ключи не кладутся: дочерний `codex exec` получает только разрешённые переменные окружения.
- На референсах бывает лицо владельца: в LLM они уходят только по кнопке vision с подтверждением,
  провайдеру — только с согласием (гейт — [generation.md](generation.md)). Где лежат загрузки и как
  долго — [architecture.md](architecture.md).
- Новый `doctor` не сохраняет сырые ответы или личный контекст: стандартный режим без inference,
  live-зонд выводит только счётчики. `data/logs/doctor/` и `docs/day0/` относятся к историческим
  проверкам Claude-моста; они не подтверждают Codex-мост.


Production prompt validation: imagePrompt содержит 40–200 слов; английская проза (русский текст
допускается внутри кавычек); motion intervals непрерывно покрывают 0–durationSec из director plan.
Это детерминированный контракт формы/длительности, а не semantic или visual continuity QC.
Регрессии alpha-аудита: `tests/{core,server}/alpha*.test.ts`, плюс unknown-submit в `gen.test.ts`.
`alphaMedia.test.ts` использует реальный ffmpeg/ffprobe и синтетическое видео, без внешних провайдеров.

Production story events-v1: цитата → beat → событие/action → startFrame → sceneId. Appearance может
заполнить только {{identity}}, остальной imagePrompt и motionPrompt неизменны. Для person/master
полный якорь, для detail без лица локальная внешность, для none текст неизменен. На new route
image reference master отсутствует физически в submit. Текстовые проверки не доказывают, что
модель исполнит событие; финальный visual critic оценивает shotMatch/startFrame и дубли.


Production B-roll: vector → independent concepts → prompts → photos → photo milestone.
contentMode=broll: ровно brollCount (1–8, default 4); нет цитат/beat. Story schema не принимает
broll как обход проверки цитат. Скрытый сценарий не отправляется агентам и не сохраняется в серии.
GeneratedBrollDraftSchema и semantic validation отклоняют неправильное число, несвязанные сцены,
буквальные дубли идей/приёмов/действий/фото и предметные none. Для 1–3 кадров все person, для 4–8 максимум один POV detail. Режиссура делает владельца главным героем, выбирает простую физику, читаемое лицо и выразительные одежду/ситуацию. Явные требования владельца не заменяются допущениями. Это не оценка творческого качества.
Режиссёр сравнивает B-roll по самостоятельной ситуации и композиции без названий одежды/цветов/мест,
не навязывает крупное лицо и фиксированную сетку приёмов. Prompter сохраняет различия крупностей
и перспективы. Критик сравнивает полные изображения разных shotId, исключая master и фрагменты;
аудит ретуши одного candidate не оценивает разнообразие версий original/current.


Production logic-v5: отсутствие wardrobeDetail, wardrobe/sceneLogic или observations одежды/логики/visualInterest отклоняет
новый ответ. Fail/uncertain части одежды понижает wardrobe и общий keep; sceneLogic не может
быть variation/not_visible. Старые отчёты сохраняются, но отсутствие новых проверок не считается
актуальной рекомендацией. Тесты labelled reports доказывают gate, не точность распознавания.
