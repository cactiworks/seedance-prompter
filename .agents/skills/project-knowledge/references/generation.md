# Генерация и деньги

## Кто запускает

Платные генерации запускает только владелец (02.10.2026): агент не жмёт генерацию ни в браузере, ни
запросом к `/api/gen/jobs`, даже с «да» в разговоре — готовит, проверяет бесплатно и называет цену.
Это правило в `AGENTS.md`; механизма нет.
12.10.2026 владелец отдельно поручил агенту провести платные проверки до Seedance. Этот ограниченный
pilot завершён: 3 Soul 2 и 1 Seedream; разрешение на видео/Topaz из него не следует.
Результаты — `docs/research/production-live-2026-10-12.md`.

## Провайдеры

KIE и Higgsfield используются только для медиа. Текстовые и визуальные LLM-агенты — Codex / OpenAI
(см. [architecture.md](architecture.md)). Таблица ниже описывает текущий каталог. Для планируемого
модуля производства владелец выбрал Higgsfield для Soul 2, Soul Cinema и Seedance 2.5; KIE — для
Seedream и upscale. Расширение каталога и эти новые маршруты ещё не реализованы.


Набор моделей задал владелец (решение 24); ключи — в Keychain, имена записей — [patterns.md](patterns.md).

| провайдер | что |
|---|---|
| KIE | всё, кроме Soul 2: GPT Image 2.5, Seedream 5 Pro, Kling 3.0, Seedance 2.5, Topaz |
| Higgsfield API (`api.higgsfield.ai`) | Soul 2 и готовые мудборды (`style_id`, список — с API, кеш на час); ключ в формате `KEY_ID:KEY_SECRET` |

- Higgsfield API — отдельный продукт с балансом в USD, мимо подписки Plus. Soul ID выбирается по имени
  в общем picker Studio, Canvas и Production; из него же доступны создание и синхронизация списка.
  API поддерживает `GET /v1/custom-references/list?page=1&page_size=20`: проверено
  12.10.2026, аккаунт вернул пустой список. Прежнее утверждение об отсутствии list endpoint устарело.
  Soul ID из веба не работал 28.09 (404); нужен completed reference версии v2 того же API-аккаунта.
  Свой мудборд через API не создаётся (решение 27).
- Soul 2 `image-to-image` доступен в текущей официальной документации: `image_url` — reference сцены,
  `custom_reference_id` — identity; это разные входы. В локальном каталоге пока только text-to-image.
  Новый endpoint не запускался; он кандидат для фиксации сцены после выявленного drift независимых кадров.
- Каталог моделей и инструментов — `src/core/gen/models.ts`; схемы, умолчания и цены у провайдеров —
  `docs/research/kie-models.md` (с датой прайса); схемы и ступени цены Topaz для картинок там нет — они в

- Как модель называет картинки в промпте, задаёт `promptRefs` в каталоге: `@ImageN` — только у

- Topaz (картинки и видео) — инструмент (`tool`): без промпта, ровно один вход, в выборе моделей студии,
  canvas и промптера его нет.

## Гейт стоимости (на сервере)

- Задача без `confirmCredits`, равного оценке каталога, → 409 `COST_CHANGED`.
- Референсы уходят провайдеру только с `refsConsent`, иначе 428: KIE передаёт запросы дальше (fal,
  replicate), на рефах бывает лицо владельца.
- Не больше 4 задач за запрос. Фактическое списание (`creditsConsumed`) пишется в задачу.
- Цена на кнопке равна гейту: цену, зависящую от входа, **меряет сервер** (`measureRefs`) — длинную
  сторону картинки по заголовку PNG / JPEG / WebP, секунды видео через ffprobe с округлением вверх и
  допуском 0.1 с. Форма берёт замер с `POST /api/gen/measure` — тот же код, что в отправке.
  Клиентским измерениям не верить; замер вне пределов параметра → 422 (решение 39, ревью PR #1).

## Задачи и хранение

- Статус опрашивает сервер (`src/server/gen/runtime.ts`), не вкладка; задачи в `data/jobs/`
  продолжаются после перезапуска.
- Файл скачивается сразу по готовности в `data/library/` — ссылки KIE живут около суток. Три попытки,
  запасная ссылка через `download-url` KIE; не вышло — `download_failed` и «Скачать снова».
- Отправка, прерванная остановкой сервера, **не повторяется автоматически**: задача могла быть создана
  и оплачена — сначала смотреть kie.ai/logs (решение 22).
- Seed есть только у Soul 2: сервер всегда отправляет конкретное число и хранит его — кадр повторяется
  через «Использовать настройки»; «Ещё раз» берёт новый (решение 27).

## Soul ID в Studio, Canvas и Production (14.10.2026)

Общий `CharacterField` показывает имя, локальное фото (если есть), статус и вариант «Без персонажа».
Выбор доступен только для completed v2 с referenceId. Неподтверждённая версия обозначается отдельно.
В Production сохраняется локальный characterId, в параметрах Soul 2 — provider referenceId (`soulId`),
который адаптер отправляет как `custom_reference_id` со strength 1. При пустом выборе оба поля отсутствуют.
Canvas хранит выбор независимо в каждой ноде; Studio запоминает его в localStorage и возвращает
после reload/смены модели. Другие модели Soul ID не получают. Старый UUID вне списка не стирается
автоматически: UI предлагает синхронизацию или новый выбор. Polling персонажей работает только
в открытом picker. Production-медиа остаются mock, выбор персонажа не делает их реальными.

Создание персонажа отдельно от mock-медиа: `POST /v1/custom-references`, обязательно
`model_version: v2`. Принимаются 1–100 локальных JPG/PNG/WebP, до 30 МБ (локальный лимит).
Перед внешней отправкой backend проверяет все файлы. Загрузка: `/files/generate-upload-url` →
PUT с выданными upload_headers без API-ключа → public_url для custom reference.
Авторизация API — Key из Keychain; credentials не передаются storage/CDN и не кладутся в env.

Цена создания Soul ID не опубликована: UI не обещает нулевую стоимость, сервер требует
`consent: true` и `costConfirmed: unknown`. Это отдельное подтверждение неизвестной цены обучения;
существующий числовой cost gate генерации кадров не меняется. Повтор одной requestId не создаёт
вторую задачу; при потерянном ответе или рестарте повторного POST нет. Ошибки не показывают сырые
ответы провайдера или signed URL. Проверять реализацию без денег — через injected SoulIdProvider.

Источники: [Soul 2](https://open.higgsfield.ai/models/higgsfield-ai/soul/v2/standard/api-reference),
[Soul ID](https://open.higgsfield.ai/models/soul-id/api-reference),
[upload](https://docs.higgsfield.ai/docs/concepts/file-uploads.md).
Общий OpenAPI Soul ID опускает model_version; используется model-specific контракт Soul 2.

## Ошибки отправки и локальное медиа (14.10.2026)

Потеря ответа submit без достоверного отказа — `unknown`, а не обычный failed. Повтор через retry
отклоняется; остаток batch не отправляется. После рестарта submitting без taskId тоже unknown.
Сначала нужна сверка истории провайдера; автоматического повторного списания нет.

Uploads/import проверяются по содержимому и декодированию, локальные результаты — до добавления
в библиотеку. Последний кадр — последний декодированный PNG, cache version `decoded-v2` обходит
прежние неточные файлы. Trim проверяет длительность источника, минимум 0.2 s и хранит точные start/end
в params; cache использует эти числа. Resize принимает чётные стороны 16–8192 px, без скрытого округления.
ffmpeg/ffprobe теперь нужны также для проверки входящих файлов.
