# Интерфейс

## Источники

- **Figma-файл Lab UI v2.1** (CC BY 4.0) — значения токенов и геометрия компонентов. Выгружен в
  `design/lab-ui/`.
- **Сайт lab.pics — эталон качества**: как система ведёт себя в собранном продукте (решение 8). Перед
  любой работой над интерфейсом — прочитать `design/lab-ui/REFERENCE.md` (измерения, принципы, таблица
  переноса, список запрещённого) и посмотреть `design/lab-ui/reference-site/home-*.png`. Новый экран
  сверяется с эталоном бок о бок скриншотом, а не по памяти.
- Раскладка и поведение оболочки — от connxn.ui (сайдбар, вкладки, лента + composer + параметры,
  библиотека, canvas); карточка работы, правка, библиотека с папками — по образцу Higgsfield
  (решения 25, 26). Кожа — всегда Lab UI.

## Правила

- В CSS приложения только `var(--lab-*)`: сырые цвета, радиусы и тени запрещены stylelint.
  `src/web/ui/tokens/tokens.css` генерируется `scripts/design/build-tokens.ts`, руками не правится.
- Шрифты — Geist и Geist Mono (подтверждено Figma-файлом, 20.09).
- Тема по умолчанию светлая; тёмная и «авто» — переключателем, выбор в localStorage (решение 20).
- Liquid glass — только на плавающем хроме; формы и превью промпта — solid.
- Интерфейс по-русски. В форме «Кадров» поля только русские (правило — [patterns.md](patterns.md),
  п. 7), английский виден в превью и строкой «в промпте: …» под полем. В студии, canvas и правке
  промпт можно писать напрямую, на любом языке.
- Всё платное — кнопка с ценой; отправка картинок провайдеру или в LLM — после согласия.
- Подтверждение опасного действия — на месте кнопки, а не диалогом: диалог встал бы под просмотр
  (решение 36).
- Компоненты UI-kit живут в галерее `/ui` во всех вариантах и состояниях; новый компонент — сначала там.
- Атрибуция Lab UI (lab.pics, lemone, Meowdes, «ported to React/CSS») обязательна: `README.md` и
  `design/lab-ui/ATTRIBUTION.md`.


## Навигация и onboarding (11.10.2026)

- Стартовый и неизвестный hash открывают Canvas. Главные вкладки: Canvas / Производство / Изображения / Видео / Материалы.
  Меню «Инструменты»: Seedance-сценарий (`#/shots`), Помощник промптов (`#/prompter`), Калибровка.
- «Как пользоваться» в шапке открывает CreatorGuide: темы по задачам, переходы на реальные экраны и
  подсветка `data-guide` anchors. Подсказку можно закрыть Esc; запусков моделей при выборе темы нет.
- На пустом Canvas — создание холста и четыре шаблона. Внутри холста «Добавить» группирует материалы,
  генерацию и обработку. Список работ в sidebar, подключения свёрнуты до запроса пользователя.
- «Сохранить схему» — JSON, «Скачать» у результата — медиафайл. «Открыть и править» в блоке открывает
  общий MediaPreview; для изображения — правку, для видео — доступный апскейл. Обрезка видео — блок Canvas.
- Меню `<details>` не закрывается на blur с `relatedTarget=null`: в WebKit это часть клика по
  кнопке. Закрытие — после выбора, по внешнему pointerdown, Esc или переводу focus наружу.
- Общая строка задач остаётся при переходах по основным экранам. «Задачи и результаты» открывает
  «Материалы» без фильтров. Незавершённые jobs отображаются до готовых файлов, ошибки не исчезают.
  Статус берётся с сервера; при сбое чтения явно показаны последние данные и время проверки.
- В MediaPreview блок «Задачи правки» показывает очереди, ошибки, unknown и готовую новую версию,
  включая правки правок. «Запущено» не означает «файл на диске»: после saved UI ждёт metadata,
  затем открывает результат. Безопасный retry — только повтор чтения статуса или скачивания.
- Подборки генераций, ролики Seedance и холсты пока отдельные сущности. Названия не должны обещать
  единый клиентский проект или автоматическую сборку финального видео.

## Production: реальные фото и demo (15.10.2026)

`#/production` по умолчанию создаёт photos-серию: сценарий/вектор → Codex-план → расчёт стоимости
и отдельное подтверждение → внешность по refs → master → обязательная проверка → кадры → финальный отбор → ручной photo milestone → проверка деталей/автоправки → выдача.
В новой серии выбор «По сценарию» / «Креативные B-roll». Для B-roll поле сценария скрыто,
появляется количество 1–8 (default 4), остаются вектор, Soul ID и Phone/Cinematic. Демо в этом
режиме недоступно. Переключение сохраняет написанный сценарий в черновике; он не уходит в запрос
B-roll. Стандартный demo-вектор про комнату убирается при первом выборе B-roll, авторский сохраняется.
В плане B-roll видны самостоятельные идеи вместо цитат; подробная постановка остаётся под раскрытием.
«Изменить замысел» возвращает заполненный brief с тем же режимом и количеством, без LLM-вызова.
Цена показывает master+n и верхнюю оценку с запасом до трёх master всего. Без Soul ID явно указана генерация без привязки
лица. Персонаж блокируется после начала фото. Inspector содержит реальный файл, prompt, task ID,
reference и оценку цены. Нет выдуманного visual QC или процента провайдера. Видео/upscale недоступны.
План раскрывается отдельно: концепция, визуальный акцент, фактура захвата, постановка кадров.
«Новая режиссура по этому сценарию» заполняет новый brief без запуска LLM. Критик — отдельный
этап с pending/running/complete/error; основная карточка показывает короткий статус и следующее действие.
Критерии, usage, prompts и история доступны через раскрытие деталей.
Milestone принимает только реальные файлы с завершённым отчётом. Все кадры выбраны
заранее; число с замечаниями показано, рекомендациями можно отфильтровать выбор. Старые серии
требуют явного согласия на передачу изображений Codex. Все исходники сохраняются.
Download/poll retry обозначен «без генерации». Unknown требует сверки в Higgsfield, не автоповтора.
Старый Codex-план можно скопировать для реальных фото без повторной квоты и mock-приёмок.
«Демо без генераций» сохраняет десять этапов и оба mock milestone. Старые mock-серии не переводятся
в платные автоматически. Codex-кнопка явно сообщает о квоте и 2–4 вызовах.
Пауза/restart сохраняют результаты, но будущие платные отправки требуют нового cost gate.

Общий Dialog: body имеет `flex: 0 1 auto`, header/footer не сжимаются. `flex: 1` при fit-content
в WebKit схлопывал тело и обрезал кнопки. Прокрутка остаётся внутри body; проверены onboarding,
photo edit и inspector в Yab (размер снимка 1024 × 640; CSS viewport/zoom не измерены).
В Chromium дополнительно проверен точный viewport 1024 × 640.

Владелец обычно открывает платформу почти на весь экран. Проверки: 1440×1000, 1280×900,
1089×900/1087×900 и 769×900/767×900 (по сторонам breakpoints), дополнительно 1024×640.

## Выбор персонажа (14.10.2026)

Блок «Персонаж · Soul ID» есть в новой и сохранённой серии. Dialog использует общий UI-kit:
список со статусами и отдельная форма создания с локальными превью, удалением из набора,
согласиями и кнопкой в фиксированном footer. Body прокручивается, footer не сжимается.
Выбрать можно completed v2; failed/unknown и неподтверждённая версия не маскируются под готовность.
Сходство лица не обещается: Soul ID применяется к реальным фото; demo-файлы остаются прежними.

Studio и генератор Soul 2 в Canvas используют тот же picker вместо ручного UUID. Компактный блок
Canvas хранит выбор для конкретной ноды, Studio помнит персонажа между открытиями. «Без персонажа»
явно снимает привязку. При выборе модели без Soul ID поле отсутствует. На мобильном picker
открывается поверх параметров Studio и возвращает focus к кнопке выбора. `Text` передаёт DOM props
и ref: Radix Dialog сохраняет aria-labelledby и доступное имя заголовка.


Исправления alpha-аудита (14.10.2026): на ширине <=768 px sidebar по умолчанию свёрнут и открывается
поверх workspace; Studio переносит параметры в modal при узкой контентной области. Library toolbar
и selection bar переносятся строками. Canvas размещает блоки с учётом занятых мест, Fit измеряет
высоту DOM; порты работают через Tab/Enter/Space, Escape возвращает focus, связи удаляются в отдельном
диалоге. Удаление холста требует повторного клика и предлагает восстановление. Общий Dialog возвращает
focus на opener. Production не закрывает читаемый этап при обновлении статуса; manual toggle имеет
приоритет. В справке есть маршрут «Серия фото или креативные B-roll» с разделением реальных фото и demo.

Photos-интерфейс: компактный путь «План → Опорный кадр → Фотографии → Твоя приёмка → Готово»,
один блок следующего действия и визуальная сетка. Приёмка — явный milestone; готовые кадры скачиваются
из карточек. «Детали производства» скрывают план, профиль, prompts, jobs, отчёты, расход и историю.
Inspector сначала показывает фото и короткий verdict; prompt/task ID раскрываются отдельно.
Отказ master показывает причину, «Пересоздать опорный кадр» с cost gate и перепроверку без генерации.
Повтор сохраняет серию, сценарий и профиль; до трёх master всего, предыдущие попытки доступны в истории.
После третьего отказа ясно указан лимит и доступна перепроверка/заполненный brief для изменения замысла.
Старый строгий отказ не становится pass автоматически. Consent перечисляет до шести refs,
до пяти Codex-вызовов и запас бюджета. Ручная приёмка не является override master gate.

В events-v1 перед запуском раскрывается компактный список «События по сценарию»: цитата, действие,
сцена и крупность. Подробные passports/startFrame/prompts остаются в деталях. Master подписан как
проверка образа, у остальных кадров своя композиция. Старые планы показывают кнопку новой режиссуры
с заполненным brief; она не вызывает LLM и не меняет существующие фото.


После milestone — компактный этап «Правки деталей». Одна кнопка считает верхнюю цену и открывает
согласие; запуск принимает замысел и включает проверку/региональные правки. До трёх правок на кадр.
Смена выбранных IDs скрывает устаревшую оценку. При лимите/сбое статус «Есть незавершённые кадры»,
короткая причина у фото, продолжение в той же серии. «Готово N из M» не объявляет всю серию завершённой.
История версий и bbox/checks под «Детали производства»; inspector позволяет посмотреть до правки.
Старые принятые кадры можно выбрать для нового post-milestone QC; уже прошедшие новый QC не запускаются
повторно случайным кликом. Новая выдача включает только кадры после проверки деталей.


Для старого photo review в milestone доступно раскрытие «Перепроверить детали крупным планом»:
отдельное согласие на Codex и фрагменты, без медиа-генерации. Успешный master не дублирует эту кнопку.
Повтор текущей проверки находится в «Детали производства». Карточка показывает короткую причину,
inspector под «Что увидел критик» — состояние каждого глаза/рта и наблюдения; главная сетка не
заполняется диагностикой. Красивое B-roll с допустимой вариацией остаётся рекомендованным.
